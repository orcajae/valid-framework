# Reproducing the Results

Install first — every tier below imports the `valid` package:

```bash
make install          # or: pip install -e ".[dev]"
```

Then one command, three tiers:

| Tier | Command | Data | Measured runtime* | What it validates |
|------|---------|------|-------------------|-------------------|
| 0 — smoke | `make reproduce-smoke` | synthetic, fixed seeds | ~0.5 min (CatBoost) / a few min (sklearn fallback, CI) | pipeline correctness end-to-end |
| 1 — default | `make reproduce` | synthetic, fixed seeds | ~16 min | the paper's *mechanism*, deterministically |
| 2 — real | `make reproduce-real` | public Binance OHLCV via ccxt (`pip install -e ".[data]"`) | download + same order as tier 1 (longer data window) | closest to the tracked reference outputs |

\* Apple Silicon laptop, Python 3.11, CatBoost 1.2. The MC stage dominates;
all other stages take seconds. Tier definitions live in
`experiments/config.py` (`FULL` / `SMOKE`).

## What runs

`experiments/reproduce_all.py` executes, in order, failing loudly on any stage:

1. **`mc_expansion.py --all`** — the Monte Carlo null-pipeline experiment:
   i.i.d.-resampled (signal-free) return series pushed through the full ML
   evaluation pipeline (features → CUSUM → triple barrier → gradient boosting
   → AUC / CPCV+PBO / permutation / net SR), 200 iterations per setting
   (seeds 0–199). Output: `results/mc_fpr_{setting}.csv` + `mc_fpr_summary.csv`.
2. **`run_variant_grid.py`** — a textbook rule-strategy panel (SMA crossover,
   RSI mean-reversion, momentum, breakout; T+1; 18bp costs) per asset.
   Output: `results/variant_grid.csv` + `variant_returns.npz`.
3. **`run_multiple_testing.py`** — Bonferroni / Holm / Benjamini-Hochberg /
   **Romano-Wolf stepdown** / DSR / Harvey-t>3 survivor counts over the panel.
   Output: `results/multiple_testing.csv`. *(Framework extension beyond the
   SSRN paper — these outputs are live-computed, never paper numbers.)*
4. **`examples/worked_example.py`** — the mined-vs-honest checklist demo.
   Output: `results/worked_example/` (reports, summary, figures).
5. **`make_summary.py`** — assembles `results/REPRODUCE_SUMMARY.md`, placing
   this run's numbers side-by-side with the tracked reference outputs.

Everything is seeded: same tier + same machine class ⇒ same numbers.

The paths above are what a run *writes*; `results/` itself is gitignored. The
reference copies to compare against are tracked under `results/reference/` —
`variant_grid.csv`, `multiple_testing.csv`, `multiple_testing.json` and
`REPRODUCE_SUMMARY.md`, alongside the corpus and audit files. Before this was
recorded, `scripts/derive_bonferroni.py` read its input from outside the
repository, so a clone could not reproduce the Bonferroni or DSR counts at all.

## How tiers relate to the published numbers

The paper's headline numbers (340 variants; MC FPR 27% [21.3%, 33.5%] →
CPCV+PBO 0% [0%, 1.9%]) come from **full real-data runs**; their outputs are
tracked in `results/reference/`. The synthetic tiers verify the *mechanism* —
a signal-free pipeline passes naive gates at high rates and CPCV+PBO gates at
near-zero rates — not the exact digits. For calibration, a tier-1 run on this
machine produced AUC-gate FPR 30.0–32.5% and PBO-gate FPR 0.0% [0%, 1.9%]
across the three settings, versus 26.5–30.0% / 0.0% in the reference runs.

Reference artifacts that are research outputs and are **not** regenerated by
any tier: `variants_340.csv` (the paper's 340-variant corpus),
`mc_null_catboost_200.csv`, `literature_audit_80.csv` (re-analyzed by
`make audit`; the paper's 85% no-code figure recomputes as 84% from the
coding sheet — a 1pp coding-sheet deviation, paper numbers canonical),
`ablation_study.csv`, `batch6_transformer.csv`, `cost_sensitivity.csv`,
`multi_asset_extended.csv`, `traditional_baselines.csv`.

Threshold note on the paper's "4.4% (15/340) exceed the benchmark": the count
uses the benchmark's net Sharpe rounded to 0.917. Against the full-precision
benchmark value (0.91732...) the count is 13 — two variants sit between the
rounded and full-precision thresholds. `variants_340.csv` lets you recompute
either way.

## Deviations from the v0.1 reference pipeline (v0.2)

Documented, deliberate, and verified before adoption:

1. **Var(SR_IS) / holdout SR indexing fix.** v0.1 computed the per-fold
   "strategy" Sharpe from raw resampled returns at misaligned (event-row)
   indices and never applied the model's positions. v0.2 applies positions to
   event-aligned T+1 forward returns. Impact was quantified by running both
   variants on identical seeds 0–199 (real BTC daily data): the legacy code
   itself re-produces a null 95th percentile of 0.342 — not the published
   0.328 — because the data window has since extended (environment drift);
   the fixed computation yields 0.430 on the same seeds. The paper's
   comparison value — real strategies' Var(SR_IS) = 0.012, computed by a
   separate, correctly-aligned pipeline — remains far below either null, so
   the flat-landscape conclusion is unchanged (and is conservative under the
   fix). The `valid/` library functions were never affected.
2. **Honest setting labels.** `eth_1h` / `sol_1h` setting keys were renamed
   `eth_daily` / `sol_daily` to match what the pipeline actually consumes.
3. **Model registry.** Reference runs used CatBoost; when it is not installed
   (core-deps CI), the pipeline falls back to sklearn
   `HistGradientBoostingClassifier` and records the model in the output. FPR
   magnitudes can shift slightly across models; the `model` column makes this
   explicit.
4. **Null resampling is i.i.d. by design** (inherited from v0.1, kept for
   comparability): it destroys serial dependence. Contrast with the circular
   block bootstrap used by `valid.multiple_testing.romano_wolf`, which
   preserves it.

## Synthetic data provenance

`experiments/data_sources.py::make_synthetic_ohlcv` — a 3-regime
(bull/bear/chop) Markov-switching GBM with Student-t(5) innovations; all
parameters are fixed in code, chosen once (documented in the module) so that
trend-following has a real, detectable edge and bear regimes genuinely hurt
buy-and-hold. The generating regime path ships in `df.attrs["regime"]`, so
bear-market evaluation is exact. Real-data downloads write a SHA-256 manifest
(`data/raw/CHECKSUMS.sha256`).
